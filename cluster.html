Designing a HPC cluster.

A two-stage national competition: a selection round designing a cluster on paper (and in the cloud), then five days on the competition floor turning a R400,000 budget into a working, benchmarked cluster. My part covered hardware selection, low-level Linux setup, and secure remote access, the layer that let four of us actually run the thing together.

Getting there: pre-round & selection round
  • Pre-round project: had to create and set up a cluster using Microsoft Azure. Created our own GitHub repository for the set-up instructions, which can be used by future competition participants.
  • Selection round: a week-long competition where, in teams of 4, we learned about High Performance Computing and then had to design a cluster optimised for a specific software (MLPerf). This included setting up the software and designing the hardware (CPU, GPU, storage specifications etc.) for the cluster.
  • Created a PowerPoint of our design and presented the idea to a panel of judges at the end of the week.
  • Created virtual cluster (3 nodes) using OpenStack and used Windows PowerShell to access cluster.
  • Rocky Linux 9.3: set up basic workings of cluster (network, system configurations etc.).

National round

  • Designed a 3-node cluster: picked CPU, storage, memory, cabling and networking requirements.
  • Servers were delivered in person at the start of the round and had to be set up from scratch: connected them together using a switch, installed operating system (Rocky Linux 9.4), created virtual network using ZeroTier to be able to remotely access cluster through Windows PowerShell using our laptops, and set up all pre-requisite software for benchmarks.
  • Various benchmarks were installed and ran across the cluster in real time. This required us to optimise our cluster in the moment to produce the fastest and best results.
  • Placed 4th and won the Fan Favourite award.
  • First ever all Women of Colour team to participate.

Reflection

This project drew directly on coursework in networking, computer architecture, and parallel/distributed computing, but the bigger lesson was leadership. As team captain, I learned to delegate and check in across four workstreams at once so every benchmark kept moving under a five-day clock. It gave me a real anchor for the professionalism courses at UCT, turning principles I'd only read about into something I could see the necessity of first-hand, and it's the closest I've come to the real trade-offs of taking a design from a budget spreadsheet through to a working, benchmarked system.
